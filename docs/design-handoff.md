# デザインデータの渡し方（XD・Photoshop）

デザイナーとコーダー向けの決まりです。XD と Photoshop には、Claude がデータを直接読む公式の仕組みがありません。
そのため **「画像」と「数値メモ」の2つ** を渡します。

- 画像だけだと、余白・文字サイズ・色が「見た目からの推測」になり、数pxのずれが出ます。
- 数値メモがあると、Claude は推測せずにその値で組みます。**数値メモの細かさが、仕上がりの正確さを決めます。**

## 渡すもの

```
design/
├── design-spec.md        … 数値メモ（docs/design-spec.template.md をコピーして記入）
├── pc/                   … PC幅のアートボード（PNG・等倍）
│   ├── top.png
│   └── news-detail.png
├── sp/                   … スマホ幅のアートボード（PNG・等倍）
│   └── top.png
├── parts/                … 細かい所の拡大（ホバー時・開いたメニュー・エラー表示など）
└── assets/               … 書き出した素材（ロゴ・アイコンは SVG、写真は元の大きさの JPG / PNG）
```

## デザイナーにお願いしたいこと

1. **アートボードの名前をページの名前にそろえる**（`top` `news-detail` など、半角英数字とハイフン）。
   書き出したファイル名が、そのままコーディングのファイル名の手がかりになる。
2. **PC幅とスマホ幅の両方を作る。** 片方しか無い所は、どう変えるかをメモに書く（例：「3列 → 1列」）。
3. **色・文字のスタイルを、XD のアセットパネルに登録して使う。** 登録した一覧が、そのまま数値メモの「色」「文字」になる。
   同じ見た目なのに値が少しずつ違う（#333 と #343434 など）状態を無くす。
4. **余白の値をそろえる。** 使う値を決めておく（例：8 / 16 / 24 / 40 / 64 / 96）。
5. **見た目が変わる状態を作る**：ホバー、フォーカス、開いたメニュー、入力エラー、0件のとき、文字が長いとき。
   無い状態は、Claude が既存の部品に合わせて作り、報告に「デザインに無かったもの」として挙げる。
6. **画像に、文字を埋め込まない。** 文字はテキストのままにする（検索と読み上げのため）。
7. **余白の測り方を伝える。** Photoshop は文字の見た目から、XD は行間を含んだ箱から測る。
   どちらで作ったページかを、数値メモの最初に書く（CSSの書き方が変わる。`.claude/rules/scss.md` の leading-trim の章）。

## 書き出しの設定

- アートボード：PNG、等倍（1x）。長いページも1枚のまま書き出す。
- アイコン・ロゴ：SVG。写真：元の大きさのまま（圧縮と WebP への変換はコーディング側で行う）。
- ファイル名は半角英数字とハイフン。日本語と空白は使わない。

## 補足：.xd ファイルを直接読ませる方法（試験的）

`.xd` は中身が ZIP で、アートボードごとの位置・大きさ・色・文字が JSON で入っています。
Claude Code に `.xd` を渡して「展開して数値を読んで」と頼むと、数値メモを書く手間を減らせる可能性があります。
ただし公式の方法ではなく、複雑なデータでは読み違えることがあります。**使うときは、読み取った値を数値メモに書き出させて、
人が目で確かめてから** コーディングに進んでください。
