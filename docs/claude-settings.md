# Claude Code の設定（禁止していること）

`.claude/settings.json` で、Claude Code が「読めないファイル」「実行できないコマンド」を決めています。
`CLAUDE.md` に文章で書くだけでは守られる保証が無いので、設定で止めています。

## 読めないファイル（`deny`）

| 対象 | 理由 |
|---|---|
| `.env`、`.env.local`、`.env.production` | パスワードなどが入っている（`.env.example` は読める） |
| `*.sql`、`*.sql.gz`、`*.sql.zip`、`*.dump` | DB の中身。顧客の個人情報が入っている |
| `wp-config.php`、`mt-config.cgi` | 本番の DB のパスワードが入っていることがある |
| `.htpasswd` | 認証のパスワード |
| `wp-content/uploads/`、バックアップのフォルダ | 顧客がアップロードしたファイル、DB のバックアップ |
| `~/.ssh/`、FileZilla の設定 | サーバーに接続するための鍵・パスワード |

ここに入れたファイルは、Claude Code は読むことも、書き換えることもできません。
`wp-config.php` を直す必要があるときは、人が直します。

## 実行できないコマンド（`deny`）

| 対象 | 理由 |
|---|---|
| `git push` | GitHub には「本番環境と同じ状態」だけを置く決まりのため。プッシュは、本番に反映したあとで人が行う |
| `sudo` | パソコン全体に影響する操作のため |
| `ssh` `scp` `sftp` `rsync` `ftp` `lftp` | 本番サーバーへの接続・アップロードは、人が行う |
| `mysqldump`、`wp db export` | DB の中身を書き出す操作 |
| `clean-dev-code.sh` | 開発環境のファイルをまとめて消すスクリプト |

## 実行の前に、必ず確認されるコマンド（`ask`）

| 対象 | 理由 |
|---|---|
| `rm` | ファイルを消す操作 |
| `git commit`、`git reset`、`git clean` | 履歴を変える・作業中の変更を消す操作 |
| `docker compose down` | `-v` を付けると、開発用の DB が消える |
| `docker compose exec db`、`wp db` | DB に直接触る操作（本番の DB を写したあとは、個人情報が入っている） |
| `curl`、`wget` | 外部との通信 |

## 知っておくこと

- **完全な壁ではありません。** コマンドの決まりは、コマンドの文字の並びで判断します。同じことを別の書き方で実行すると、
  すり抜けることがあります（公式ドキュメントにも、そう書かれています）。
  「うっかりを防ぐ仕組み」であって、「何をされても安全」ではありません。**個人情報の入ったファイルは、そもそも案件フォルダに置きっぱなしにしない**のが基本です。
- より強く止めたいときは、Claude Code のサンドボックス機能（OS の仕組みで、ファイルと通信を制限する）があります。
  このキットでは、まだ設定していません。
- 自分のパソコンだけの設定を足したいときは、`.claude/settings.local.json` に書きます（Git には入りません）。
  ただし、`deny` に入っているものを、あとから `allow` で許可することはできません。
- いま効いている決まりは、Claude Code で `/permissions` と入力すると見られます。
- この設定を変えるときは、キット（元の雛形）の側を直します。案件の中だけで緩めないでください。

参考：https://code.claude.com/docs/en/permissions
