# AI でコーディングする案件の雛形（Claude Code ＋ Eleventy）

Claude Code（AI）と一緒に、**デザイン → 静的コーディング → WordPress への組み込み** を進めるための雛形です。
AI に守らせるルール・作業の手順（コマンド）・ビルドの仕組みが入っています。案件ごとにコピーして使います。

- **Claude Code** … AI にコードを書かせ、実行させる道具
- **Eleventy（イレブンティ）＋ EJS** … 部品に分けたファイルから、静的な HTML を作る道具
- **Sass** … CSS を書きやすくする言語。ビルドのときに CSS に変換する

## 入っているもの

```
.
├── CLAUDE.md               … 案件全体のルール（AI が毎回読む）。【 】を案件ごとに書く
├── .claude/
│   ├── rules/              … ファイルの種類ごとの書き方（SCSS・HTML・JS・静的コーディング・WordPress）
│   ├── commands/           … 作業の手順（/design-to-code など）
│   ├── settings.json       … AI に読ませないファイル・実行させないコマンド
│   └── launch.json         … 開発用サーバーの起動の設定（ポート 8090）
├── docs/
│   ├── workflow.md         … 工程ごとの担当（AI と人）とチェックリスト
│   ├── design-handoff.md   … デザイナーからコーダーへの、データの渡し方
│   ├── design-spec.template.md … 数値メモ（色・文字・余白）のひな形
│   ├── claude-settings.md  … settings.json で禁止していることの説明
│   └── verification-ejs-to-wp.md … 検証メモ（ejs で作ってから WordPress に移す）
├── eleventy.config.js      … ビルドの設定（EJS → HTML、SCSS → CSS）
├── package.json            … 使う道具とコマンド
└── .gitignore              … GitHub に上げないもの
```

**この雛形には、`src/`（コードの元のファイル）と `design/`（デザインのデータ）は入っていません。**
どちらも案件ごとに作ります。顧客の情報が入るため、`.gitignore` で GitHub に上げないようにしています。

## 用意するもの

- Node.js 22 以上
- Claude Code（デスクトップアプリ、または ターミナル）
- デザインのデータ（XD・Photoshop）と、数値メモ（`docs/design-handoff.md` を参照）

## 始め方

### 1. 雛形をコピーする

案件用のフォルダに、この雛形の中身をコピーします。GitHub の「Use this template」を使ってもかまいません。

### 2. 道具を入れる

```bash
npm ci
```

### 3. `CLAUDE.md` の【 】を書く

案件名・CMS とそのバージョン・テーマの種類・関数の接頭辞・本番サーバー・開発環境の URL・可変の基準幅などを書きます。
**ここが空のままだと、AI が推測で進めてしまいます。** 決まっていない所は、決まった時点で書き足します。

- 使わない CMS の行は消してください。
- 案件の中で決めたことは、「決定事項」に日付と理由を添えて書き足します。

### 4. `package.json` の名前を変える

`"name": "wp-kit-template"` を、案件の名前（半角英数字とハイフン）に変えます。

### 5. デザインのデータを置く

```
design/
├── design-spec.md   … 数値メモ（docs/design-spec.template.md をコピーして書く）
├── pc/              … PC 幅のアートボードの画像（PNG・等倍）
├── sp/              … スマホ幅のアートボードの画像
├── parts/           … ホバー・開いたメニューなど、細かい所の画像
└── assets/          … 書き出した素材（ロゴ・アイコンは SVG、写真は元の大きさ）
```

くわしくは `docs/design-handoff.md` を見てください。XD の場合は、`.xd` ファイルから数値メモの下書きを AI に作らせることもできます
（試験的。読み取った値は、必ず人が XD の画面で確かめます）。

### 6. `src/` を作る

**`src/` が無いと、ビルドが止まります。** 最初のコマンド（`/design-to-code`）で AI が中身を作りますが、
その前に `npm run dev` を試すときは、空の `src/` を作っておいてください。

```bash
mkdir src
```

## コマンド

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発用のサーバーを起動する（http://localhost:8090/）。ファイルを保存すると、自動で作り直す |
| `npm run build` | `dist/` に、納品用のファイル（HTML・CSS・JS・画像）を出力する |

- SCSS（`src/assets/scss/style.scss`）は、ビルドのときに `dist/assets/css/style.css` に変換されます。
  出力された CSS は直接編集しません。
- `dist/` の HTML は、ファイルを直接開いても正しく表示されません（パスが `/` 始まりのため）。開発用のサーバーで見てください。

## AI に頼む作業（Claude Code のコマンド）

Claude Code の入力欄に、`/` から始まるコマンドを送ります。

| コマンド | 内容 | 使う工程 |
|---|---|---|
| `/design-to-code ページ名` | デザインの画像と数値メモから、ページをコーディングする | 静的コーディング |
| `/static-check` | 静的 HTML がデザインと合っているかを確かめ、CMS に進んでよいかを報告する | 静的 HTML の確認 |
| `/static-to-wp` | 静的 HTML を、WordPress のテーマに置き換える | CMS の実装 |
| `/pre-delivery` | 納品前のチェック（ビルド・アクセシビリティ・SEO・パフォーマンス・セキュリティ）をまとめて行う | 納品前の確認 |

例：

```
/design-to-code top
スマホのデザインはありません。数値メモのスマホの欄と、PC のデザインから組んでください。
```

工程の順番と、AI と人の担当は `docs/workflow.md` にあります。

### 頼むときのこつ

- **1回の依頼は、1ページ（または1つのパーツ）まで。** まとめて頼むと、確かめきれない量が一度に出てきます。
- **共通パーツ（ヘッダー・フッター・ボタン・見出し）を先に作る。** あとのページが使い回すので、見た目がそろいます。
- **出てきたものは、その場で表示して確かめる。** 直してほしい所は「どこが・どう違うか」を具体的に伝えます。
- **同じ注意を2回したら、ルールに書く。** `CLAUDE.md` か `.claude/rules/` に書き足すと、次から言わなくて済みます。

## AI にさせないこと

`.claude/settings.json` で、次のことを AI ができないようにしています（くわしくは `docs/claude-settings.md`）。

- `.env`・DB のダンプ・`wp-config.php`・アップロードされたファイルなどを読むこと
- `git push`、`sudo`、本番サーバーへの接続（`ssh` `scp` `rsync` `ftp` など）、DB の書き出し

ほかに、`CLAUDE.md` の「Claude がやらないこと」に、人が行う作業をまとめています
（本番の操作、プラグインの追加・更新、デザインに無い要素を勝手に足すこと、など）。

## GitHub に上げるときの注意

- **`src/`・`design/`・`dist/`・`.env` は上げません**（`.gitignore` で除外しています）。顧客の情報・写真・ロゴが入るためです。
  一度コミットすると、あとで消しても履歴に残ります。
- コミットに記録されるメールアドレスに気をつけてください（公開のリポジトリでは、誰でも見られます）。
- 案件のリポジトリには、「いまの本番環境と同じ状態」だけを置く決まりです。`git push` は、本番に反映したあとで人が行います。

## まだ用意していないもの

- `/pre-delivery` が使う `npm run a11y`（axe-core によるアクセシビリティのチェック）は、`package.json` にまだありません。
  使うときは、案件ごとに追加してください。
- `CLAUDE.md` から参照している `.claude/rules/movabletype.md`・`static-php.md` は、この雛形には入っていません
  （WordPress ＋ Eleventy の案件用の雛形のため）。

## ライセンス・出典

- 外部のライブラリを `src/` に入れるときは、出典とライセンスの表記を残してください
  （例：スライダーの Splide は MIT ライセンス。圧縮した CSS には表記が無いので、ファイルの先頭に書き足す）。
