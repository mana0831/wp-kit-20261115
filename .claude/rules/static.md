# 静的コーディングのルール（CMS に組み込む前の HTML）

デザインから、まず静的な HTML を作る。CMS に組み込むのは、そのあと。
マークアップの決まりは `html.md`、作り方（道具ごとの書き方）は、案件に合わせて次のどちらかに従う。

- PHP のインクルードで作る：`.claude/rules/static-php.md`（WordPress の案件の標準）
- Eleventy + EJS で作る：`.claude/rules/static-ejs.md`（Movable Type・PowerCMS X・CMS なしの案件の標準）

どちらで作るかは、案件の `CLAUDE.md` に書いてある。

## 1. なぜ、先に静的 HTML を作るのか

デザインとのずれには、2種類ある。

| 種類 | 例 | 原因のある場所 |
|---|---|---|
| コーディングのずれ | 余白の値の間違い、画面の幅を変えたときの崩れ、フォントの指定漏れ | HTML・CSS |
| CMS の仕様とのずれ | CMS が出力する HTML がデザインと合わない、文章が長いと崩れる、0件のときの形が無い | デザインと、CMS の仕組みの相性 |

- **静的 HTML の段階で、デザインと合っていることを確かめておく。** そうすれば、CMS に組み込んだあとでずれたとき、
  「CMS の側の問題」と絞り込める。作業が2つのチームに分かれているので、この切り分けが大事になる。
- **静的 HTML は、CMS に組み込んだあとの「正解の見本」になる。** 組み込んだページと並べて、見比べられる。
- CMS の仕様とのずれは、組み込みの段階で見つかると、デザインからやり直しになる。
  **静的 HTML の中で、CMS の出力と、中身が変わったときの状態を再現して、先に見つける**（§3・§4）。

## 2. 成果物

静的コーディングが終わったとき、次がそろっていること。

| 成果物 | 内容 |
|---|---|
| 全ページの HTML | デザインのあるページすべて。共通パーツ（ヘッダー・フッターなど）は、1か所にまとめてある |
| CSS・JS・画像 | 元のファイル（SCSS など）と、出力したファイル |
| 本文の見本ページ | CMS のエディタで入力する本文の、見た目の見本（§3） |
| 状態の見本 | 中身が変わったときの表示（§4） |
| ページの一覧 | 全ページへのリンクを並べた、確認用のページ（公開しない） |
| 引き継ぎメモ | CMS を実装する人に伝えること（§6） |

## 3. 本文の見本ページ

CMS のエディタで入力する本文（お知らせの本文など）は、入力する人が中身を決める。デザインには、その一部しか描かれていない。

- 本文の枠（クラス名は `CLAUDE.md` に従う）の中で使える部品を、**すべて並べた見本ページ**を作る：
  見出し（`h2`〜`h4`）、段落、リンク、太字、箇条書き、番号付きの箇条書き、表、画像（左右寄せ・説明文つき）、
  引用、ボタン、区切り線、ファイルへのリンク、動画の埋め込み。
- **HTML は、その CMS が実際に出力する形で書く。** 自分で考えた HTML で作ると、組み込んだあとで合わなくなる。
  - WordPress（ブロックエディタ）：ブロックが出力する HTML とクラス（`wp-block-〇〇`）を、そのまま写す。
    WordPress 本体が出力する CSS も、見本ページに読み込む（`static-php.md` §4）。
  - Movable Type など：エディタが出力する HTML を、管理画面で入力して確かめてから写す。確かめられないときは、
    「未確認」として引き継ぎメモに書く。
- デザインに無い部品の見た目は、既存の部品に合わせて作り、引き継ぎメモに「デザインに無かったもの」として挙げる。

## 4. 状態の見本

CMS に組み込むと、中身は顧客が入れる。デザインどおりの文字数・件数とは限らない。次の状態を、静的 HTML で作って確かめる。

| 状態 | 確かめること |
|---|---|
| 文章が長い | タイトル・カテゴリ名・ボタンの文字が、デザインの2〜3倍になっても崩れない |
| 文章が短い・無い | 1文字や空でも、余白や線が不自然にならない（任意の項目は、項目ごと出ない形も作る） |
| 件数が0件 | 「お知らせはありません」などの表示がある |
| 件数が1件・多い | 1件だけのとき、列が崩れない。多いとき、ページ送りが出る |
| 画像が無い | 代わりの画像か、画像なしの形がある |
| 画像の縦横比が違う | 縦長・横長の画像でも、枠が崩れない |
| フォーム | 入力エラー、確認画面、完了画面 |

- 全部の組み合わせを、ページとして作る必要は無い。一覧のページに「長いタイトルの項目」を1つ混ぜる、などで足りる。
- 別のページにしたほうが見やすいもの（0件、エラー）は、ページを分ける。

## 5. CMS に組み込みやすく書く

- **共通パーツの境目を、CMS のパーツの境目と同じにする**（ヘッダー、フッター、`<head>` の中、パンくずリスト、一覧の1件分）。
- **くり返す部品は、1件分をひとまとまりにして書く**（CMS では、そこがループになる）。
- CMS から出す値（タイトル、日付、リンク先、画像）と、固定の文字を、見分けられるようにする。
  仮の値は、本物らしい長さ・形で入れる（日付は実在する日付、リンク先は `#` ではなく想定するパス）。
- CMS を実装する人への指示は、HTML のコメントで、決まった形で書く。あとで検索して、消し忘れを見つけられる。

```html
<!-- CMS: ここから一覧のループ（1件分） -->
<li class="c-news-list__item">…</li>
<!-- CMS: ここまで -->

<!-- CMS: トップページだけ h1、ほかのページは div -->
```

- **クラス名・`js-` フック・`aria-*`・`id` は、組み込んだあとも変えない前提で付ける。**
  ほかのテンプレートやプラグインと重ならない、具体的な名前にする。
- ページごとに違う値（`<title>`、説明文、`body` のクラス、いまのページの印）は、ページの先頭の変数にまとめる。

## 6. 引き継ぎメモ

静的コーディングが終わったら、CMS を実装する人に向けて、次を書く（`docs/handoff.md`）。

- ページの一覧と、それぞれに使う想定のテンプレート
- 共通パーツの一覧と、渡している値
- 変えてよい所・変えてほしくない所（クラス名、`js-` フック、`aria-*`、HTML の入れ子）
- JS が動く条件（必要な HTML の形、読み込む順番）
- デザインに無かったので補ったもの、確かめられなかったもの
- 本文の見本ページと、状態の見本の場所

## 7. やらないこと

- 静的 HTML の中で、CMS の関数・タグを使わない（CMS が無くても表示できること）。
- 確認用のページ（ページの一覧、見本ページ）と、静的 HTML のフォルダを、本番に置かない。
- デザインと合っていないことに気づいたまま、CMS の実装に進まない。合わせきれない所は、理由と一緒に報告する。
