`design/` の画像と数値メモをもとに、ページをコーディングする。対象：$ARGUMENTS

## 手順

1. **読む**
   - `design/design-spec.md`（数値メモ）。**数値はここに書かれた値を正とし、画像から読み取った値で上書きしない。**
   - `design/pc/` と `design/sp/` の対象の画像、`design/parts/` の関係する画像。
   - 既存の共通パーツ（`include/`）と部品（`object/component/`）。同じ見た目の部品があれば、新しく作らずに使う。
2. **足りないものを質問する**（1回にまとめる。答えが無くても進められるものは、推測して進める）
   - スマホのデザインが無い、状態（ホバー・エラー・0件）が無い、数値メモと画像が食い違う、など。
3. **組み立ての案を出す**（コードの前に、短く）
   - セクションごとの「HTMLの要素（`section` `article` `nav` など）」「見出しのレベル」「使う部品（既存 / 新規）」「必要なJS」。
   - 初回（トークンがまだ無いとき）は、数値メモの色・文字・余白を `foundation/_root.scss` と `global/` に先に定義する。
4. **コーディングする**：`.claude/rules/` の決まりに従う。上から1セクションずつ進める。
   - 画像の素材は `design/assets/` から使う。無い素材は、勝手に作らず報告に挙げる。
5. **表示して見比べる**
   - 開発サーバーでページを開き、数値メモの「PCのアートボードの幅」と「スマホのアートボードの幅」でスクリーンショットを撮る。
   - デザインの画像と並べて、違いを直す。**2回直しても合わない所は、それ以上くり返さず報告に挙げる。**
   - その間の幅（タブレットなど）でも、崩れていないことを確かめる。
6. **報告する**
   - 作った・変えたファイル。
   - **推測した値の一覧**（数値メモに無く、画像から読み取ったもの。場所・入れた値）。← 人が必ず確かめる。
   - デザインに無かったので補ったもの（状態・スマホ表示など）。
   - 合わせきれなかった所、確かめていないこと。

## 守ること

- デザインに無い要素・文言を足さない。仮の文言が要るときは、仮であることがわかるように書き、報告に挙げる。
- 推測した値を、推測のまま黙って使わない。必ず報告の一覧に入れる。
