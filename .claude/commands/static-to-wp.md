静的コーディングの成果物を、WordPress のテーマに置き換える。対象：$ARGUMENTS

## 手順

1. **テーマの種類を確かめる**
   - `CLAUDE.md` の「テーマの種類」を読む（クラシック / ブロック / ハイブリッド）。
     **書いていなければ、ここで止めて質問する**（種類で作り方がまったく変わるため）。
   - `.claude/rules/wordpress.md` と、種類に合うルール（`wordpress-classic.md` か `wordpress-block.md`）を読む。
2. **調べる**（まだファイルは作らない）
   - `/static-check` の結果を確かめる。静的 HTML がデザインと合っていないまま、組み込みを始めない
     （合っていない所があれば、ここで止めて報告する）。
   - 静的 HTML（`document_root/_html/` か `dist/`）の全ページと共通パーツ（ヘッダー・フッターなど）を一覧にする。
   - `theme-preset/`（テーマのひな形）があれば、中身を読む。`functions.php` とブロックエディタの拡張は、ここから始める。
   - `docs/workflow.md` の「更新箇所の一覧」を読む。空なら、ここで止めて記入を頼む。
3. **設計の表を出して、確認を待つ**
   - **クラシックテーマ**：ページごとに「使うテンプレートファイル」「投稿タイプ」「管理画面で変えられる項目と入力方法」。
   - **ブロックテーマ**：上に加えて、部品ごとに「標準のブロック / パターン / 独自ブロック」のどれで作るか
     （`wordpress-block.md` §3）と、`theme.json` に入れるトークンの一覧。
   - **ハイブリッドテーマ**：クラシックの内容に加えて、`theme.json` に入れる色と幅、使うブロックエディタの拡張
     （`wordpress-classic.md` §5）、本文の枠に必要な見た目の一覧。
     静的 HTML のままでは保てない所（標準のブロックにすると HTML・クラスが変わる所）を、はっきり挙げる。
   - 判断に迷う所は、選択肢を2〜3個とおすすめを書く。
   - **人が OK を出すまで、テーマのファイルを作らない。**
4. **共通部分から作る**
   - クラシック・ハイブリッド：`functions.php`（`theme-preset` のひな形から）、`theme.json`、`header.php`、`footer.php`、`template-parts/`。
   - ブロック：`theme.json`、`functions.php` と `inc/`、`parts/`、独自ブロック、パターン、最後に `templates/`。
5. **ページを1つずつ作る**：1ページ作るごとに、開発環境の URL で表示して静的 HTML と見比べる。
   見た目・動き・`aria-*` が変わっていないことを確かめてから次へ進む。
   ブロックテーマは、サイトエディターでそのテンプレートを開き、「無効なコンテンツ」のエラーが出ないことも確かめる。
6. **報告する**
   - 作ったファイルの一覧と、それぞれの役割。
   - 管理画面で人が行う設定（固定ページの作成、パーマリンク、メニュー、プラグインの設定など）。
   - 静的 HTML から変わった所（ブロックテーマで、HTML・クラスが変わった部品）。
   - 確かめたこと・確かめていないこと。

## 守ること

- 独自のテンプレート・独自ブロックでは、クラス名・`js-` フック・`aria-*`・`inert` を変えない。
- 出力はすべてエスケープする。
- プラグイン・ビルドの仕組みを勝手に追加しない。必要なら候補と理由を出して、判断を待つ。
- 本番の DB・サーバーには触らない。`git push` しない（GitHub には、本番と同じ状態だけを置く決まり）。
