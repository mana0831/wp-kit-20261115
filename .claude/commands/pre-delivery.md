納品前のチェックを行い、結果を1つの表で報告する。**このコマンドでは、見つけた問題を勝手に直さない**
（直すかどうかは報告のあとで人が決める）。

## チェックの内容

1. **ビルド**：`npm run build`。失敗したら、エラーを報告してここで止める。
2. **アクセシビリティ**：`npm run a11y`（axe-core）。`critical` / `serious` の違反を、ファイル・要素・直し方とともに挙げる。
3. **HTML**（全ページ）
   - `h1` が1つで、見出しの順番が飛んでいない。
   - `<title>` と `meta description` がページごとに違う。`lang="ja"` がある。
   - 画像に `alt` `width` `height` がある。最初の画面に出ない画像に `loading="lazy"` がある。
   - `id` が重なっていない。リンク切れ・空の `href` が無い。
4. **CSS・JS**
   - `!important`、直接書いた色（16進数）、生の `@media` など、ルールから外れた書き方が無い。
   - `console.log` や使っていないコードが残っていない。
5. **WordPress**（テーマがあるときだけ）
   - エスケープしていない `echo`、無害化していない `$_GET` / `$_POST`、`prepare()` を通していないSQLが無い。
   - `WP_DEBUG` を有効にして各ページを開き、エラーや警告が出ない。
   - くわしい確認は、WordPress のセキュリティ監査のスキルで行う（使える場合）。
6. **残っているもの**：仮の文言（「ダミー」「テキスト」「lorem」）、開発用のURL（`127.0.0.`、`localhost`）、`TODO`。

## 報告の形

| 区分 | 結果（OK / 要対応 / 未確認） | 件数 | 内容 |
|---|---|---|---|

- 「要対応」は、重いものから順に、ファイル名と行・理由・直し方を書く。
- **機械では確かめられないもの**（キーボードでの操作、スマホ実機、デザインとの見た目の一致、文言の正しさ）は、
  「人が確認する項目」として最後に並べる。
